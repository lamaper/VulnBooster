# 基于小模型辅助的数据增强技术路线

## 1. 研究目标重述

本课题的核心目标不是直接升级最终漏洞检测器，也不是单纯追求生成更多漏洞代码，而是：

**构建一个由小模型辅助的数据增强流程，生成高质量漏洞增强数据集，并证明该数据集可以稳定、可观地提升下游漏洞检测模型性能。**

因此，整个研究系统应该明确拆分成两个层次：

1. **上游：增强数据构造系统**
   - 负责切片、筛选、生成控制、质量过滤与数据回灌。
   - 这是论文创新的主要落点。

2. **下游：漏洞检测验证平台**
   - 负责验证增强数据集是否真的有用。
   - 这里应尽量固定基线模型，避免与上游创新点混淆。

## 2. 核心研究问题

围绕这个目标，建议将课题收敛为以下四个核心问题。

### 2.1 如何以较低成本逼近 LLM 的增强辅助能力

现有方案中，LLM 在增强流程中承担了高成本但高质量的语义裁剪、上下文提纯和候选样本筛选工作。  
课题的核心突破点就是研究：

> 能否训练一个小模型，以更低成本复现或逼近这类辅助能力。

### 2.2 小模型应该介入增强流程的哪个位置

在当前论文方案中，小模型最适合介入的位置不是最终检测器，而是增强链路的中前段，具体包括：

1. 原始函数的漏洞相关区域切片
2. 候选增强样本的筛选
3. 生成提示上下文的压缩
4. LLM 生成结果的质量打分

本课题建议优先聚焦第 1 项，即：

**训练一个小模型切片器，替代原始 LLM 的语义切片/辅助筛选工作。**

### 2.3 如何定义“小模型切片器”的监督信号

小模型不能凭空学会切片，需要教师信号。当前最可行的教师就是现有流程中已经产出的高质量结果：

- Joern 静态切片结果
- LLM 初筛结果
- LLM 融合精炼结果 `refined_code`

其中，最适合作为主监督信号的是最终 `refined_code`，因为它已经融合了结构先验与语义修正。

### 2.4 如何证明增强数据集真的有效

必须把“增强流程表现好”与“最终检测模型受益大”区分开来。  
最终需要证明两件事：

1. 小模型辅助增强流程生成的数据质量高
2. 这些增强数据能稳定提升多个下游漏洞检测模型

## 3. 总体技术路线

建议按“三阶段路线”推进。

### 阶段 A：教师级增强监督构造

目标：利用现有 LLM 流程构造监督数据。

输入：

- 原始函数 `func`
- Joern 静态切片结果
- LLM 初筛结果

输出：

- 教师级精炼切片 `refined_code`
- 切片对应的保留行集合

具体做法：

1. 对原始函数做基础清洗
2. 跑 Joern 静态切片
3. 跑 LLM 初筛
4. 跑 LLM 融合精炼
5. 将 `refined_code` 对齐回原始函数，得到行级标签

这一阶段的产物不是直接发论文的最终成果，而是后续训练小模型切片器的监督资产。

### 阶段 B：小模型切片器训练

目标：训练一个低成本模型去预测哪些代码行应该被保留。

推荐任务定义：

1. **行级二分类任务**
   - 输入：完整函数
   - 输出：每一行是否属于漏洞相关区域

2. **候选片段打分任务**
   - 输入：候选片段
   - 输出：该片段作为增强上下文的质量分数

建议优先选择行级二分类，因为实现最直接、监督最清晰、最容易跑通。

输入：

- 原始函数文本
- 每行的位置信息

监督：

- 教师切片保留行作为正类
- 未保留行为负类

输出：

- 保留行掩码
- 或按得分排序的关键行集合

### 阶段 C：基于小模型切片的增强数据集构造

目标：用小模型切片器替代原先高成本的 LLM 切片辅助步骤。

输入：

- 验证集漏报样本
- 原始函数
- 小模型切片结果

流程：

1. 小模型切出高密度漏洞相关上下文
2. 将该上下文用于增强生成或增强控制
3. 生成候选漏洞样本
4. 进行语法校验、去重、过滤
5. 合并成增强训练集

输出：

- `small_model_augmented_train.jsonl`
- 与原方案平行的增强数据集版本

## 4. 小模型在增强流程中的推荐位置

### 方案一：替换 LLM 初筛

原流程：

`原函数 -> LLM 初筛 -> llm_slice`

新流程：

`原函数 -> 小模型切片器 -> semantic_slice`

优点：

- 替换位点清晰
- 最符合“LLM 切片换小模型切片”的表述

缺点：

- 仍可能需要后续轻量融合

### 方案二：替换 LLM 融合前的语义选择器

原流程：

`Joern 切片 + LLM 初筛 -> LLM 融合`

新流程：

`Joern 切片 + 小模型语义选择 -> 轻量融合/直接输出`

优点：

- 更贴近“结构先验 + 语义判别”的组合逻辑

缺点：

- 实现更复杂

### 方案三：作为生成前的上下文压缩器

原流程：

`FN 样本原函数 -> LLM/模板增强`

新流程：

`FN 样本原函数 -> 小模型切片 -> 压缩上下文 -> LLM/模板增强`

优点：

- 不必完全替换生成模型
- 更容易先获得成本收益

缺点：

- 创新点会偏“辅助生成优化”

### 当前最推荐

优先做：

**方案一 + 方案三**

也就是：

1. 先让小模型承担语义切片职责
2. 再把切片结果用于增强生成输入压缩

这样既容易实现，又能和现有代码最自然衔接。

## 5. 小模型监督信号设计

## 5.1 监督来源

优先级建议如下：

1. `refined_code`
2. `llm_slice`
3. `code_lines` / `static_slice`

其中：

- `refined_code` 最适合作为主教师
- `llm_slice` 可作为辅助教师
- `static_slice` 可作为结构先验或弱监督

## 5.2 标签形式

### 形式一：行级硬标签

定义：

- 如果原函数某一行出现在教师切片中，则标签为 1
- 否则为 0

优点：

- 简单直接
- 最容易先跑通

缺点：

- 对近邻上下文不够柔和

### 形式二：行级软标签

定义：

- 教师保留行为高分
- 与教师行相邻的上下文行为中等分
- 完全无关行为低分

优点：

- 更接近真实切片边界的不确定性

缺点：

- 标签构造更复杂

### 形式三：候选片段排序标签

定义：

- 给定多个候选片段
- 教师最终选择的片段为正
- 其他片段为负

优点：

- 更适合做 reranker

缺点：

- 需要构造候选片段池

### 当前最推荐

先做：

**行级硬标签**

后续再扩展到软标签或排序标签。

## 6. 小模型选型建议

这里的小模型是“增强辅助模型”，不是最终漏洞检测器。

### 推荐主选

1. `CodeBERT-base`
   - 稳定
   - 社区认知度高
   - 可直接改造成行级分类器

2. `CodeT5-small`
   - 更轻量
   - 适合做轻量替代和成本对照

### 可选补充

3. `GraphCodeBERT-base`
   - 如果后面想利用图信息，可作为增强版切片器

4. `BiLSTM / TextCNN`
   - 用作极轻量成本对照

### 当前最推荐策略

第一阶段只选一个：

**CodeBERT-base 作为小模型切片器**

原因：

- 能力和稳定性更均衡
- 工程实现最简单
- 更适合尽快拿到第一批结果

## 7. 下游验证模型建议

下游模型不应该作为主要创新点，应固定为验证平台。

推荐至少选 2 到 3 个：

1. `CodeBERT-base`
2. `GraphCodeBERT-base`
3. `CodeT5-small` 或 `UniXcoder-base`

作用：

- 验证增强数据集是否具备模型无关收益
- 避免论文被质疑“只对一个模型有效”

## 8. 实验组设计

建议最少包含以下实验组。

### 8.1 数据集构造对比

1. `Original`
   - 原始训练集，不增强

2. `LLM-Aug`
   - 原始 LLM 增强方案

3. `SM-Aug`
   - 小模型辅助增强方案

4. `Hybrid-Aug`
   - 小模型切片 + LLM 生成的混合方案

### 8.2 切片器能力对比

1. `Static Slice`
2. `LLM Slice`
3. `Small Model Slice`
4. `Static + Small Model`

### 8.3 下游检测对比

在固定下游模型上比较：

1. 不增强训练
2. 原 LLM 增强训练
3. 小模型增强训练

## 9. 指标设计

### 9.1 小模型切片器指标

- Precision
- Recall
- F1
- Jaccard / IoU
- 与教师切片的平均重合率

### 9.2 增强数据集质量指标

- 语法通过率
- 去重后保留率
- 平均每个种子样本产生的有效增强数
- 平均生成耗时
- 平均调用成本

### 9.3 下游漏洞检测指标

- Recall
- F1
- MCC
- Balanced Accuracy
- 可选 Precision

本课题尤其应强调：

**Recall 和 F1**

因为增强的目标就是缓解漏报。

## 10. 蒸馏策略建议

本课题里的“蒸馏”不建议理解为：

- 直接把通用大模型蒸成最终漏洞检测器

更合理的理解是：

**用 LLM 增强流程的高质量结果，蒸馏出一个小模型切片器或小模型筛选器。**

### 推荐蒸馏对象

1. 切片边界
2. 保留行集合
3. 候选片段排序
4. 样本质量分数

### 当前最推荐的蒸馏路线

1. 现有 LLM 流程作为 teacher
2. `CodeBERT-base` 作为 student
3. 学习教师级 `refined_code` 对应的保留行标签
4. 将 student 用于增强数据构造

## 12. 推荐的实现顺序

为了尽快产出可用结果，建议按下面顺序做。

### 第一步

保留现有 LLM 教师流程，先把教师切片数据稳定产出。

### 第二步

把教师切片对齐到原始函数，构造行级监督数据集。

### 第三步

训练第一版 `CodeBERT` 小模型切片器。

### 第四步

让小模型切片器替代增强流程中的 LLM 切片辅助步骤。

### 第五步

生成新的增强训练集，并在固定下游检测模型上验证。

### 第六步

做成本、时间与性能对比，形成论文主结果。

## 13. 一句话总结

最终建议将课题收敛为：

> 利用现有 LLM 流程构造教师级增强监督，训练小模型接管高成本的切片辅助任务，生成可显著提升多个漏洞检测模型性能的高质量漏洞增强数据集。

这条路线和你们当前代码、老师建议、论文目标以及大创结题需求是最一致的。
