# V3/V4 基线冻结

冻结日期：2026-07-10

## 1. 冻结目的

从当前阶段开始，`v3` 与 `v4` 增强生成器不再作为“待大改模块”，而是作为稳定基线保留，用于后续对比：

1. `CodeBERT line_slicer + v3/v4 generator`
2. `CodeT5 slicer + v3/v4 generator`

也就是说，后续主攻点转为：

1. `CodeT5` 切片器改进
2. 生成前后的筛选器改进
3. 在不破坏 `v3/v4` 已有收益的前提下，继续推高 precision

## 2. 冻结范围

### 2.1 冻结的研究结论

当前已经可以视为稳定结论的是：

1. 锚点约束、非平凡变异过滤、语法修复可以把增强样本从“能生成”推进到“能产生检测收益”。
2. 机理感知生成 `v4` 是成立的，且在默认阈值口径下给出了当前更稳的结果。
3. 现阶段没有必要推翻 `v3/v4` 生成器主结构，下一步应重点优化切片器和筛选器。

### 2.2 冻结的工程边界

当前默认不主动改动下面这些主逻辑，除非明确需要修 bug：

1. `src/vulnbooster/augmentation.py` 中 `v3/v4` 的主 prompt 结构
2. `src/vulnbooster/augmentation.py` 中锚点与非平凡性基本约束
3. `src/vulnbooster/validation.py` 中已有 AST / detector / quality rerank 基本主流程

允许继续改进的方向是：

1. `CodeT5` 切片预测与候选选择
2. 基于切片质量的附加筛选
3. 更偏 precision 的门控参数与重排策略

## 3. 冻结成绩

### 3.1 检测器基线

测试集默认阈值：

- Precision: `0.6875`
- Recall: `0.8250`
- F1: `0.7500`
- MCC: `0.4593`

### 3.2 V3 当前最强结果

依据 `docs/stage_experiment_report_2026-07-10.md`：

- Precision: `0.7556`
- Recall: `0.8500`
- F1: `0.8000`
- MCC: `0.5795`

这个结果说明：

1. `v3` 已经证明增强数据对下游漏洞检测器有显著正收益。
2. 少量高质量增强样本也能带来明显提升。

### 3.3 V4 当前最稳结果

默认阈值口径：

- Precision: `0.7333`
- Recall: `0.8250`
- F1: `0.7765`
- MCC: `0.5292`

这个结果说明：

1. `v4` 在不牺牲 recall 的情况下，precision 和 MCC 仍优于基线。
2. `v4` 更适合作为后续 `CodeT5` 切片器实验的稳态生成器基线。

## 4. 结论与后续口径

从这一刻开始，后续汇报里建议固定如下口径：

1. `v3`：展示“增强上限潜力”
2. `v4`：展示“默认阈值下的稳态结果”
3. `CodeT5` 后续实验：默认挂接在冻结后的 `v3/v4` 基线上做并行对比

## 5. 下一阶段目标

下一阶段不再问“增强生成器是否有效”，而是问：

1. `CodeT5` 切片是否比当前 `CodeBERT line_slicer` 更适合服务增强链路
2. 更强的切片候选选择与筛选门控，能否把最终 precision 推到 `0.78 ~ 0.80`
3. 这种提升是否还能保持当前 recall / F1 / MCC 不明显退化
