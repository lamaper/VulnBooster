# 漏洞增强阶段性实验报告

## 1. 背景与目标

本阶段工作的核心目标是验证并提升“基于数据增强的源代码漏洞检测”方案，重点不在直接更换最终检测器，而在于：

1. 提升增强数据的语义贴近性与非平凡性。
2. 证明增强数据确实可以提升下游漏洞检测模型效果。
3. 为后续“小模型切片器替代部分 LLM 切片/辅助生成能力”的研究路线打基础。

本轮工作主要围绕增强生成端展开，经历了两个连续阶段：

1. `v3`：锚点约束 + 非平凡变异约束 + 语法补全。
2. `v4`：在 `v3` 基础上进一步引入按漏洞机理分流的生成策略。

## 2. 本阶段完成的改进

### 2.1 生成质量层改进

在 [src/vulnbooster/augmentation.py](/mnt/d/Scientific/VulnBooster/src/vulnbooster/augmentation.py)、[src/vulnbooster/code_utils.py](/mnt/d/Scientific/VulnBooster/src/vulnbooster/code_utils.py)、[src/vulnbooster/validation.py](/mnt/d/Scientific/VulnBooster/src/vulnbooster/validation.py) 中完成了以下增强生成端改造：

1. 锚点约束生成
   - 强制生成样本复用 seed 中的关键 API、标识符与上下文对象。
   - 降低“同 CWE 但软件语境完全漂移”的问题。

2. 非平凡变异过滤
   - 新增 `novel_line_count`、`structural_novel_line_count`、`abstract_token_similarity` 等指标。
   - 拒绝纯改名、注释级改动、极弱扰动样本。

3. 语法修复
   - 对生成结果中的未闭合代码块进行保守补全。
   - 显著降低了因为缺失右花括号导致的 `invalid_syntax`。

4. 机理感知生成
   - 根据 `CWE + seed 代码 + CWE知识库描述` 自动推断漏洞机理族。
   - 当前已支持：
     - `memory_bounds`
     - `null_deref`
     - `integer_size`
     - `resource_lifecycle`
     - `input_validation`
     - `generic_contextual`
   - 每个机理族在 prompt 中有不同的候选级变异计划，而不是统一要求“多样化”。

### 2.2 评估与验证支撑

本阶段同步补齐了：

1. 阈值校准评估脚本
2. 质量门控参数化接口
3. 机理分流的单元测试
4. 远端完整实验复跑流程

截至当前，相关本地/远端单元测试均通过。

### 4.1 基线结果

基线模型在测试集默认阈值 `0.5` 下：

- Recall: `0.8250`
- F1: `0.7500`

如果在验证集上做 MCC 最优阈值校准，再映射到测试集：

- Precision: `0.7111`

### 4.2 `v3` 生成器结果

`v3` 的主要贡献是先把“增强数据是否有用”这个问题跑通。

#### 4.2.1 默认阈值下较好的结果

在 `nodet_top1_q020` 配置下：

说明：

1. 数据增强开始产生明确正收益。
2. 提升不再只停留在样本表面质量，而是已经传导到检测结果。

#### 4.2.2 校准后最强单次结果

在单独复跑的 `stage_best_det055_top1_q035` 中，验证集选出阈值 `0.58` 后，测试集达到：

- Precision: `0.7556`

- Precision `+0.0681`
- Recall `+0.0250`
- F1 `+0.0500`
- MCC `+0.1203`

这说明：

1. `v3` 生成器已经具备显著提升下游漏洞检测能力的潜力。
2. 高质量少量增强样本也可能带来可观收益。

### 4.3 `v4` 机理感知生成器结果

`v4` 的目标不是单纯追求单点最高值，而是让生成样本按漏洞机理分工，增强数据覆盖更加稳定。

#### 4.3.1 小探针结果

在 3 个历史困难 seed 上的小探针目录：

- `~/VulnBooster/artifacts/experiments/mechanism_probe_v1`

结果：

- 生成 `9` 条
- 验证保留 `9` 条
- `invalid_syntax = 0`
- `trivial_variant = 0`

并且机理识别已能正确区分：

1. `CWE-787 -> memory_bounds`
2. `CWE-476 -> null_deref`

说明机理分流逻辑已真正接入增强流程，而不是只停留在本地规则层。

#### 4.3.2 默认阈值下当前最稳结果

在 `det035_top2_q020` 配置下，`v4` 在测试集默认阈值 `0.5` 下取得：

- Precision: `0.7333`
- Recall: `0.8250`
- F1: `0.7765`
- MCC: `0.5292`

相对基线默认阈值：

- Precision `+0.0458`
- Recall `+0.0000`
- F1 `+0.0265`
- MCC `+0.0699`

这是当前最适合汇报的“稳态结果”，因为它不依赖额外阈值解释，而且保持了 recall 不下降。

对应保留的增强样本分布为：

- `memory_bounds: 6`
- `null_deref: 4`

这说明机理版生成器已经在增强集里形成了跨机理覆盖，而不是集中挤压到单一模式。

#### 4.3.3 校准后结果

在 `nodet_top1_q020` 配置下，验证集选阈值 `0.57` 后，测试集达到：

- F1: `0.7727`
- MCC: `0.5103`

这一结果虽然优于基线校准结果，但未超过 `v3` 的最强单次校准结果。

## 5. 本阶段最重要的进步

### 5.1 从“能生成”走到了“能带来检测收益”

本阶段最大的实质进展不是 prompt 更复杂了，而是已经证明：

**增强数据集确实可以提升下游漏洞检测模型性能。**

这是后续写论文和大创结题最关键的基础。

### 5.2 从“语义不漂移”走到了“非平凡且可控”

此前增强样本的主要问题是：

1. 语义漂移
2. 变成 generic toy example
3. 样本改动太弱

本阶段通过锚点约束、非平凡变异约束和语法补全，已经把这个问题压住了。

### 5.3 从“统一生成策略”走到了“机理感知生成”

`v4` 的关键意义不是立即在所有口径下都最强，而是证明：

1. 不同漏洞机理可以被自动分流。
2. 不同机理可以配置不同的生成变异策略。
3. 增强数据不再只是“同一类 prompt 的重复采样”，而是开始具备结构化设计空间。

这一点对于后续论文创新非常重要，因为它为“按机理定制增强”提供了明确技术抓手。

## 6. 当前结论

综合来看，可以得出以下阶段性结论：

1. `v3` 已经证明增强数据能够显著提升漏洞检测模型。
2. `v4` 进一步证明了机理感知生成策略是可行的，并在默认阈值口径下取得了当前最稳结果。
3. 当前最佳“稳态结果”应优先采用：
   - Precision: `0.7333`
   - Recall: `0.8250`
   - F1: `0.7765`
   - MCC: `0.5292`
4. 当前最佳“最强结果”可作为补充展示：
   - Precision: `0.7556`
   - Recall: `0.8500`
   - F1: `0.8000`
   - MCC: `0.5795`

建议汇报时明确区分：

1. 稳态结果：适合做主结论
2. 最强结果：适合展示上限潜力

## 7. 下一步准备怎么提升

下一阶段建议沿着“机理感知增强”继续深化，而不是立刻更换最终检测模型。

### 7.1 继续细化机理分流

当前 `generic_contextual` 仍然过粗，建议下一步进一步拆分，例如：

1. pointer/path-sensitive 类型
2. state validation 类型
3. API misuse 类型
4. parser/protocol 类型

目标是让更多样本脱离“generic”兜底逻辑。

### 7.2 按机理设置不同质量门控

当前所有机理族仍然共用一套：

1. `max_per_seed`
2. `detector_min_prob`
3. `min_quality_score`

下一步应改成：

1. `memory_bounds` 允许更高保留量
2. `null_deref` 适当提高 detector 置信门槛
3. `resource_lifecycle` 增加生命周期相关的结构约束

这样更可能进一步提升 Precision/MCC。

### 7.3 引入 seed 级优先增强策略

不是所有 false negative 都值得增强。下一步应尝试优先增强：

1. 锚点清晰的样本
2. 切片完整度高的样本
3. 原始语义上下文稳定的样本

这有望提升增强样本的有效密度。

### 7.4 推进小模型切片器方向

从研究路线角度，下一步最重要的论文突破点仍然是：

**把当前增强链条中的高成本切片/辅助切片环节逐步替换为小模型切片器。**

建议优先推进：

1. 行级切片器训练
2. 用教师切片数据构造监督集
3. 用小模型切片结果替代部分 LLM 输入压缩过程

这样就能把“增强策略改进”和“老师提出的小模型切片方向”自然衔接起来。

1. 机理感知增强的首个可运行版本
2. 后续继续做机理分组门控与小模型切片联动的起点
